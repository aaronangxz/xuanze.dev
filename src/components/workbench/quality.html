Case study · iOS #357

before~1 in 5full-suite runs failed on a flaky capture-flow test
→
after0 / 225runs failed: 200× the suite, 25× the full suite (12,175 tests)
  1. Proved the cause. Marking the view model @MainActor made the test build fail on main-actor state used off-actor. The race is stated by the compiler, not guessed from a flake.
  2. Fixed without collateral. Image processing stays off the main thread; only the write-back hops to main.
  3. Proved the fix by amplification, under the exact condition that produced the flake.
  4. Filed what else it found. Amplification exposed a separate timing flake (a 500 ms sleep margin). It was tracked on its own, not absorbed into this fix.
