The test workflow in mobile-qa-agent, annotated 
# Unit tests on every push and PR. No devices or API keys:
# the suite runs on fakes. Live device runs and the model
# eval suite are manual (they need simulators and cost money).
permissions:
  contents: read                                ← ①
strategy:
  fail-fast: false
  matrix: { python-version: ["3.12", "3.13"] }  ← ②
steps:
  - uses: actions/checkout@11bd719…             ← ③
  - uses: actions/setup-python@0b93645…
  - run: python -m pytest -q                    ← ④

What each line buys

  • ① The token can read the repo and nothing else, so a compromised step can't push.
  • ② Both supported Pythons; one failing version doesn't hide the other's result.
  • ③ Actions pinned to commit SHAs, not movable tags, so an upstream retag can't change what runs.
  • ④ Fakes only: free, fast, no secrets in CI. The expensive checks are deliberate and manual.

The budget behind it: the pre-merge suite stays under ~10 minutes, and slower tiers run on a schedule.
