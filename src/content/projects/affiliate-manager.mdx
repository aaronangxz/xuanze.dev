## The problem

<Draft>
The client sold services through independent affiliates. Bookings arrived over chat, payments were checked by hand, and commissions were worked out in a spreadsheet at the end of each month. Nobody, the affiliates included, could easily see where a sale came from or what they were owed.
</Draft>

## What I built

Three front ends on one Go API:

- **Booking site.** Customers pick a slot, pay and get a confirmation. Built with Next.js.
- **Owner portal.** Leads, bookings, affiliates and payouts in one place.
- **Affiliate portal.** Each affiliate sees their own leads, sales and earnings.

## How it fits together

```text
customer  ──▶ booking site  (Next.js) ──┐
owner     ──▶ owner portal  (React)   ──┼──▶ API (Go) ──┬──▶ MySQL  orders, leads, commissions
affiliate ──▶ affiliate portal        ──┘       ▲       └──▶ Redis  sessions, response cache
                                                │
                             payment provider ──┘ webhooks
```

## Decisions worth explaining

<Draft>
### Attribution is stored on the order

The referral code is captured at booking and saved with the order, together with the commission rate at that moment. Changing an affiliate's rate later never rewrites past earnings.

### Payment webhooks are idempotent

Each provider event ID is recorded in the same transaction that marks an order paid, so a retried webhook is a no-op instead of a double booking.
</Draft>

### Every cache key gets an expiry

Early on I cached API responses in Redis with no TTL and ended up with thousands of stale keys next to session tokens. [I wrote up the cleanup](/writing/delete-redis-keys-that-matches-pattern).
